# Office 编辑、版本保存与渲染验收

## 已实现

- 招标材料、企业材料和成果 Office 文件均从现有预览页进入编辑模式，不再把招标材料固定为只读。
- 原始上传/成果源文件不动。在后台编辑工作副本解除 DOCX 批注保护，用户直接编辑正文；DOC/XLS/PPT 先转换为对应 OOXML 工作副本。
- Office 原生保存和预览栏保存按钮均进入正式保存选择：创建新版本或覆盖当前版本。自动暂存仅为草稿，不自动创建正式版本。
- 创建新版本保留旧版，并显示在原文件夹下的“历史版本”；覆盖所选版本时保留恢复备份。原始上传文件另有不可变副本。
- 保存请求与回调关联，支持幂等、并发覆盖冲突、超时、桥服务重启恢复；失败不谎报保存成功，也不自动重复提交未知结果。
- 文件切换遇到未正式保存修改会提示；保存后再次打开定位到已保存版本，而不是退回之前版本。
- Office 文件名按实际转换格式提供下载扩展名。

## 字体

当前 DocumentServer 已安装、校验并注册 6 个开源中文字体文件：思源宋体 Regular/Bold、思源黑体 Regular/Bold、朱雀仿宋、霞鹜文楷。许可、固定版本、SHA256 和下载脚本见 `infra/onlyoffice/fonts/`。

编辑工作副本将缺失的宋体、黑体、仿宋等引用映射到这些真实 family；预览栏信息图标披露替代关系。原件不改。

**替代字体不是微软原版，不保证相同字形或分页。** 精确复现原字体仍需相应服务器使用授权。朱雀仿宋为上游预发行版。实测浏览器编辑分页与 PDF 打印分页也可能不同，正式提交应按最终导出件核验，不能直接沿用旧页码。

## 图片与文档保真

9 份项目 207 DOCX 中，6 份源件带批注保护，3 份原本没有。全部编辑工作副本均无启用保护；全部源 SHA256 与正式版本列表在只读验收前后不变。

- 补充文件：173 张原始 JPEG、173 次引用/绘制。
- 专项响应文件：165 张独立图片、271 次引用/绘制。
- 其余 7 份源 DOCX 未嵌入图片，不能自动补出源文件本来没有的扫描件。
- 338 个媒体条目的压缩字节、解压内容及图片关系在工作副本准备阶段完全保留。
- 已检查实际页面上的扫描件、印章、二维码、架构图。Docs PDF 使用 Pattern 中的图片资源，普通图片枚举为 0 不能判断丢图。
- 补字体后的真实浏览器中，补充文件第 25 页扫描图、专项响应文件第 43 页架构图均完整可见。该次专项响应编辑会话为 622 页，独立打印转换为 640 页，不能承诺屏幕页码与打印一致。
- 专项响应文件源 PNG 顶部的小字重叠在原图中已存在，不属于字体替代或编辑器生成的新问题。

## 保存实际操作验收

独立测试文件 `office-save-qa-20260905/protected-edit-save-fixture.docx`，不属于项目成果。测试源 SHA256：`e45bb426ddf3eb7f56c5dbe96cdd8bb35e9962b304edc24ebec1ca02931f17ef`。

1. 受保护源件打开后，工具栏可用，正文实际输入新版本标记，图片可见。
2. 点击 Office 原生保存出现选择框，创建 V1；原件和版本 0 均不变。
3. 追加覆盖标记后覆盖 V1，备份 SHA 精确匹配覆盖前 V1。
4. 重新打开后内容、图片、字体仍在；不追加正文也可另存 V2。
5. V2 再追加外层保存标记，选择框经过多次轮询不消失；使用外层保存按钮覆盖成功，保留第二份备份。
6. 最终版本 0、1、2 和两份备份可独立下载；21 项最终内容、保护、图片与 hash 检查全部通过。

证据在忽略目录 `.local-artifacts/office-save-evidence-20260905/` 与 `.local-artifacts/office-image-audit-20260905/`，未将真实原文写入代码或测试快照。

相关前端回归 65 项通过；桥接/字体测试 63 项通过，下载扩展名补丁的 store 回归 22 项通过。TypeScript、相关 ESLint 和 backend-mode 构建通过（仅有现有 bundle 大小提示）。

## 部署范围与使用

这是本机 `4173` 预览编辑链路和本机 Office 桥服务的变更；正式修订保存在 Docker `editor_versions` 数据卷。BidVolt API 继续连接 `47.100.182.3:28123`，没有修改远端 API 或源成果包。当前整包下载仍是远端生成的成果包，不包含本机 Office 后续修订；编辑后可单独下载保存版本。

已有编辑会话请关闭文件、刷新页面并重新打开，避免继续使用旧保护会话或旧字体缓存。字体已在运行容器注册；compose 中也已加入字体持久化挂载，后续重建 DocumentServer 后按字体 README 再次刷新校验。
