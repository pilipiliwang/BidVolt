# 消息发送与本地队列修复（2026-09-05）

## 已确认的问题

- 远端 `47.100.182.3:28123/openapi.json` 的 POST `/api/v1/projects/{project_id}/agent-run/{task_id}/chat` 描述为向同一会话追加消息并返回回复，不是独立的快速入队回执接口。
- 原页面把所有已提交请求放进“正在加入队列”，只有 `queued === false` 才移除；未包含 `queued` 的正常回复仍可能永久留在队列。
- 任务完成后 SSE 已结束，发送消息并不会自动重开旧任务流。原先 `reply` 仅显示在全局提示，没有进入主对话记录。
- 成果工作区没有传入调整方向、删除回调，按钮始终禁用；更多按钮只是额外的展开全文模式，现已按用户要求移除。

## 当前行为

1. 没有本页未结束请求时，第一条立即提交到原项目主会话；等待回复的消息显示在对话记录中。
2. 请求未结束时，后续普通消息暂存当前页面，按 FIFO 顺序发送。队列条只代表还没有提交的消息。
3. 删除仅取消真正未提交的本地条目；调整方向移出本地队列，以 `mode=steer` 提交一次。不复制已经提交的消息，也不伪称后端撤回。
4. 返回的 `reply` 直接展示为 BidVolt 输出。`queued=true` 且无回复显示“后端已排队”；成功未带 `queued` 不会永久留队。
5. 等待超时及网络/5xx 等不确定结果显示“结果待确认”，不自动重试同一条消息，也不恢复附件诱导重发。明确拒绝或非零 `returncode` 才显示失败。
6. 同一任务的 `sessionId` 补全不会清空队列；任务切换、卸载及企业切换后的迟到结果不会污染新会话。

## 远端限制与验证边界

当前远端 OpenAPI 没有队列查询、已提交消息原位调整或删除接口。当前本地队列及直接回复记录不提供跨刷新恢复；刷新/离开页面会丢失尚未提交的本地条目。完整持久队列仍需要 FE-ASSISTANT-005 至 008 的服务端契约。

已通过组件、队列状态机、完成任务回复展示和透传测试；使用不连接 API 的独立本地回归页验证了实际按钮与回复 UI。未向真实项目发送测试消息，未撤回、重发用户此前的消息。
