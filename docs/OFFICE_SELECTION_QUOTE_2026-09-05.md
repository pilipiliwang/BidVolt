# Office 选区引用修复（2026-09-05）

## 行为

- 在 Office 中选中文字，点击页签工具栏的“引用到对话框”，将文件来源与实际选区正文插入消息草稿；不会自动发送。
- 草稿中的引用和修改要求都可编辑。发送以当前草稿为准，不再偷偷追加最初选区原文。
- 删除引用标签时，只删除仍然完整保留的原始引用块；用户已改写的文字不会被误删。
- 未选中文字时显示明确提示，不再降级为“引用当前文件”。成功后的“已引用当前文件”浮动提示已删除。
- 切换或关闭文件会取消尚未完成的选区读取，避免把旧文件回调插入新草稿。

## 原因与实现

原实现依赖当前 Community Document Server 未提供的 `createConnector` Automation API，失败后仅引用文件名。本地编辑桥接服务现在在签署编辑会话配置前加入隐藏的 Plugins API 选区组件，用只读的 `GetSelectedText` 获取选区。

插件与前端通过每次会话生成的 channel、精确 origin、绑定窗口和 requestId 通信；不读取剪贴板，不修改文档，不调用 Agent API。当前仅允许本机 HTTP(S) origin，不能直接作为云端多租户授权方案。

已适配本机 ONLYOFFICE 9.4 的插件相对 URL 拼接、语言参数追加，以及无查询参数的 config.json 初始化请求。修改 Node 桥接模块后需重启 editor-bridge，已有文档需重新打开以加载新插件。

## 验证

- 前端选区通信、Office 组件、引用草稿及 Office 集成：36 项测试通过。
- 插件配置、来源校验、空选区、超时和 SDK 初始化兼容：16 项 Node 测试通过。
- 涉及的 TypeScript 文件 ESLint 通过。
- 真实浏览器：项目 207 的授权委托书虽仍受源文件保护，但选中的第一段正文已成功进入输入框，且可在草稿内改写和追加要求；没有浮动成功提示。
- 验证没有发送真实 Agent 消息，也没有修改文档正文。该修复不解除源文件保护，不代表 Agent 的实际改稿回写已被本次验证。
