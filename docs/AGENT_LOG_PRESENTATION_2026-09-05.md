# Agent 上下文记录分类与展示

## 本次核对

BidVolt API 仍通过本机 `/api/v1` 代理连接 `http://47.100.182.3:28123`。
在项目 207 的现有任务 3499 页面核对历史日志，没有发起新任务或发送测试消息。

当前前端 SSE 契约接收 `message { seq, kind, content }` 和 `end { status, outcome, reason, action_list, error }`。
远端公开 OpenAPI 没有定义完整 SSE 消息 schema，不能假设后端已经提供 `channel/final/message_id` 等可靠的正文标识。

实际历史内容中，同一个 `hermes` 类型包含终端启动信息、Reasoning 分析、工具命令、分片代码、diff 和正式回复。
`┌─ Reasoning` 后不一定有结束线；`╭─ ⚕ Hermes` 是切换到公开回复的重要边界。只按单条前缀判断会漏出代码尾片，或错误地把后续正式回复全部折叠。

## 展示规则

- 2026-09-05 补充：明确的 system/service/tool/command 等运行事件显示实际文本，不整条替换成“系统记录（内部详情已隐藏）”。统一产品名及工作目录显示；内部推理仍不展示，内部分类占位不作为日志列表项渲染。
- 用户消息：右对齐浅绿色气泡，保留发送状态。
- 正式回复：近黑正文、浅色圆角卡片、绿色左边线。
- 明确的错误、交互问题、待办提示：保持可见，保留既有处理入口。
- 系统、工具等运行记录默认折叠，展开后显示实际文本；明确的内部推理及无法确认边界的终端片段不展示。
- 展开后以安全的纯文本保留日志，不执行 HTML 或解析运行日志中的 Markdown。
- 不再按命令首行去重，避免吞掉同一命令的不同执行结果。

## 分类策略与边界

实现：`src/shared/ui/agent-timeline-classification.ts`。
先按序号排序，再跨相邻片段识别终端框、代码围栏、diff 与公开回复边界。
保留流片段的空白和缩进。混合消息按段区分，关键结论不会仅因包含文件路径、`json.dump` 等代码名称就整段隐藏。
明确类型的普通运行文本可见；未知原始终端片段须识别公开回复边界。现有无结构日志仍是保守启发式分类，不保证完全准确。

后续若要做到可靠的语义分层，后端应按统一事件契约提供公开正文/工具/分析通道、消息 ID、消息完成状态和是否需要用户响应等字段。
本次不臆造这些字段，也不修改远端服务。

## 回归范围

分类样本覆盖真实终端标记、无 footer 的 Reasoning、跨片标题/代码、Unicode 变体、中文标题、错误/问题保留、路径与代码词误判、空白分片，以及同命令不同结果。
UI 验证包括单条与多条默认折叠、展开原文、流更新保持展开选择、用户消息、问答提交、任务切换和工作台集成。
